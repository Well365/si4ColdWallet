# W1 费曼汇报：观察机的"发送体系"——节点可选、gas 可选、先查余额

日期：2026-10-11 · 状态：代码与模拟器编译完成，已装到两台真机；测试网实际发一笔需要你的测试币（见第 7 节）

> 费曼法：如果不能用大白话讲给外行听懂，就说明自己还没真正弄懂。讲不清的地方，就是要补的缺口。

## 1. 一句话

联网的那台手机（观察机）现在能自己选"用哪个节点发"、选"手续费给多少"，并且在让签名机签字之前先算清楚钱够不够。

## 2. 讲给外行听

寄快递有三个问题：交给哪个快递点、选普通还是加急、钱包里的钱够不够付货款加运费。
- **节点 = 快递点。** 以前每条链只认一个快递点，它关门你就寄不了。现在每条链内置好几个，能一键"体检"（是不是这条链、到了第几个区块、多快），还能加自己的；签好的交易可以换一个快递点再投。
- **gas = 运费档位。** 以前是系统替你定一个价。现在列出"慢 / 标准 / 快"三档，每档写明单价和"最多要付多少"，也能自己填。档位按最近 10 个区块别人实际付的价钱算（10%、50%、90% 三个分位），不是随口给的。
- **先查余额。** 以前钱不够也会生成二维码，到广播时才失败。现在构造前先算"金额 + 最多运费"，不够就直接告诉你差在哪。
- **运费和货款不会混。** 签名机和观察机都多了一行"总计最多扣除（金额 + 最高手续费）"；转代币时写"最多扣除（仅手续费）"——金额一行、手续费一行、总数一行。

## 4. 怎么证明它是对的

- Rust 全部测试：`cargo test --workspace --locked --offline` → 179 个通过，0 失败（本机实测）。其中新加：三档规则（已知输入得到已知结果、偶数个取中位数、BNB 链基础费为 0、全为 0 报错、溢出、历史太长）、余额核对（恰好够 / 差 1 wei / 代币不够 / 溢出）、C 接口往返、"总计最多扣除 = 0.050063 BNB"。
- clippy：自有代码 0 警告；rustfmt 一致。
- 内置节点：2026-10-11 用 `eth_chainId`、`eth_feeHistory`、`eth_maxPriorityFeePerGas` 逐个实测，只保留能用的；不通的（LlamaRPC、1RPC、rpc.sepolia.org）没放进去，不支持 `eth_feeHistory` 的 Cloudflare 也没放。Esplora 实测了创世区块、区块高度和两种费率接口。
- 构建：C6 两路径复现一致；观察机模拟器版编译通过且无新警告；签名机编译通过（产物检查 C4/C5 仍是已知的 Xcode 27 问题）。
- **未验证**：真机上的实际发送与广播（要测试币）。

## 5. 我讲不清 / 没把握的地方（知识缺口）

| 缺口 | 为什么讲不清 | 怎么补 | 何时补 |
|---|---|---|---|
| 三档在拥堵时是否够用 | 只用了 10 个区块的历史，暴涨时"快"也可能不够 | 真机测试网多发几笔，看确认时间；必要时调倍数 | 有测试币后 |
| 公共节点长期可用性 | 今天能用不代表明天能用 | 节点页的体检 + 允许加自建节点 | 持续 |
| 节点说谎的影响 | 节点可以报假余额、假手续费 | 签名机独立显示"总计最多扣除"并对异常手续费告警；后续可做多节点交叉核对 | 后续 |
