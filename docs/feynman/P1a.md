# P1 费曼汇报（上半程）：工具链与供应链底座

日期：2026-10-10 · 状态：P1 上半程完成；独立审查结论见第 8 节；下半程见 `P1b.md`

## 1. 一句话

我们搭好了一条"只吃源码、断网做饭、每道菜都验过"的流水线，并用它做出了第一个能在 iPhone 模拟器里运行、通过自检的签名机骨架。

## 2. 讲给外行听

想象一个只用自家菜园的厨房：

- **菜从哪来**：不去超市（包仓库）买包装好的成品菜，而是直接去原产地（作者的 git 仓库）摘某一天、某一垄（固定 commit）的菜，每棵菜称重拍照（算目录指纹）登记在册。
- **做饭时锁门断网**：厨房里缺什么就做不成，绝不临时叫外卖。
- **出锅前三道检查**：①菜和登记册对得上吗（指纹）；②里面有没有混进不认识的东西（二进制扫描）；③做好的菜里有没有"联网"这味调料（符号检查）。
- **每道检查都要演一次"抓贼"**：故意往菜里放一颗石子，确认检查真的会报警。

这次就真的碰到了一颗"石子"：rust-bitcoin 依赖的一个小库 `hex_lit`，超市里卖的 0.1.1 版说自己产自某一垄，可原产地根本没有这一垄。它不一定有毒，但来路说不清，我们就不吃——自己种了一棵（40 行代码，带测试）。

还碰到一次"检查走过场"：签名库编译后，我们的接口函数被优化器整个删掉了，于是"没有联网调料"的检查通过了——因为锅里几乎是空的。发现后改了编译方式，并加了一道"链接探针"：用一段 C 程序把每个接口都真的调用一遍，少一个就编不过。

## 4. 怎么证明它是对的

| 证据 | 结果 |
|---|---|
| `cargo test --workspace --locked --offline` | 29 个测试全部通过：BIP39 官方 24 组向量（熵→助记词、助记词→熵、种子）、BIP32 根私钥 24 组、BIP84 官方地址 3 个、C 接口正反用例 |
| `cargo clippy -- -D warnings` | 我们自己的代码零警告（禁止 unwrap/expect/panic，禁止网络与进程类型） |
| C1 指纹 / C2 二进制 / C3 来源 | 全部通过 |
| C7 libsecp256k1 核对 | 153 个文件逐字节一致 |
| C8 链接探针 | iOS 真机与模拟器两版均链接成功；在 iPhone 16 Pro 模拟器中运行：自检 0、BIP84 地址正确、错误助记词被拒（-3） |
| C4/C5 对最终 App 二进制 | Signer.app 无网络相关导入符号，只链接苹果系统框架与 Swift 运行库 |
| C6 可复现（单机两路径） | 真机版 `c3b81bc0…8755`、模拟器版 `eee06756…bc44`，两路径逐字节一致 |
| 反向对照 | 把可执行文件改名为 .txt 放进仓库 → C2 失败；给第三方 README 加一个空格 → C1 失败；对 `/usr/bin/curl` 跑 C4 → 失败 |
| 模拟器截图 | `build/screens/p1-signer-selftest.png`：自检通过，地址与 BIP84 官方向量一致 |

**没有验证的**：真机运行（没有设备）、第二台电脑复现、开发者证书断网行为（D1–D4）、第三方源码的人工逐行审查。

## 8. 独立审查结论

共做了四次独立审查：一轮 Rust 代码审查，三轮供应链与 iOS 外壳的安全审查。后两轮都是"复核上一轮的修复"，审查人每次都要实际动手绕过。所有 CRITICAL、HIGH 已处理并做了反向对照。

| 轮次 | 范围 | 发现 | 处理 |
|---|---|---|---|
| Rust 审查 | `core/` 中的秘密处理与 C 接口 | 无 CRITICAL/HIGH。1 个 MEDIUM：第三方 HMAC 和 `Xpriv` 在栈上留下残留——"助记词异或 0x5c"8 处（12 词时可直接还原助记词），根私钥、根链码各 1 处。另有 7 个 LOW | `SecretXpriv` 释放时擦除；PBKDF2 只建一次带密钥的 HMAC；接口返回前擦除 64 KiB 栈。复测全部 0 次。LOW 也已全部修复：补 15/21 词向量、出错时输出参数置空、指针对齐检查、头文件 C++ 保护等 |
| 安全审查一 | 工具链安装、引入脚本、检查脚本、Xcode 工程、Swift | 1 个 CRITICAL：C1 可被绕过（缺 MANIFEST 也"通过"、隐藏目录不检查、目录名被当成正则）。7 个 HIGH：C2/C3 的正则与通配漏洞、上级目录 Cargo 配置、C4 只是黑名单、产物检查可被静默跳过、工具链锁文件可被覆盖、Xcode 链接未核验的库 | 检查全部改用 `aw.py` 重写（D15）；工具链改官方独立安装包并固定哈希（D14）；签名机接口改会话句柄，秘密只在 Rust（D16）；Xcode 以显式 `.a` 路径链接；新增 C9、C10 |
| 安全审查二 | 复核 | 4 个 HIGH：build.rs 能改写仓库里的固定哈希和白名单；无扩展名的 `.cargo/config` 不受检查；C4 可被直接系统调用和"数据区里的 dlsym 指针"绕过；`env.sh` 漏清 `XCODE_XCCONFIG_FILE` 等变量（实测能往链接参数里塞一个额外的库）。另有 5 个 MEDIUM | 编译放进沙箱、只能写 `target/`；工具链目录指纹固定在仓库；`.cargo/` 严格检查；检查 `svc` 指令；环境变量清理并在构建前核对实际链接参数；MEDIUM 全部修复（C2 改为遍历文件系统、白名单限定目录、发布门槛要求两人审查等） |
| 安全审查三 | 复核 | 3 个 HIGH：构建脚本可通过终端 `TIOCSTI` 逃出沙箱；`target/` 里的中间产物可被替换且不会被发现；C4 看不到 `__text` 以外的代码和数据区里的函数指针 | 见 P1b 费曼汇报第 4 节 |

**最大的教训**：每一轮都在"检查本身"里找到了真实的绕过方法。检查脚本也是代码，同样需要对抗式审查和反向对照；任何一个"通过"，都要先证明它能"不通过"。
