> 费曼法：如果不能用大白话讲给外行听懂，就说明自己还没真正弄懂。讲不清的地方，就是要补的缺口。

## 1. 一句话

签名机现在能看懂"结构化签名"（EIP-712），会把每一个被签名的字段完整列出来，并一律要求勾选确认后才签。观察机能发起这类签名请求。另外按你的要求加了两项：
- **passphrase 模式**：输两次；可以核对预期指纹，输错就进不去。
- **区块浏览器网址**：签名机上只显示文字，观察机上可以点。

## 2. 讲给外行听

**结构化签名是什么**：很多网站不让你发交易，而是让你"签一份表格"。表格里写着"谁、授权给谁、多少额度、到什么时候"。签完以后，对方可以拿着这份签名去链上，替你把授权或挂单"兑现"。你不用再签任何交易，钱可能就被转走了。这是近几年最常见的钓鱼手法：
- Permit、Permit2：链下授权。
- Seaport：NFT 挂单，比如"0 元把你的 NFT 卖给我"。

**签名机怎么防**：
1. **严格读表**：
   - 表格（JSON）里出现重复的键，拒签。
   - 多一个字段、少一个字段，拒签。
   - 数字超出声明的范围，拒签。
   - 地址的大小写校验不对，拒签。

   这样能保证"屏幕上显示的"和"被签名的"是同一份内容。
2. **完整显示**：表格里的每一个字段都列出来，不截断。太长的字段（超过 1024 字节）显示不完，直接拒签，因为看不完就等于盲签。
3. **认得的给摘要，认不得的给警告**：
   - 认得的类型：代币 Permit、DAI 式 permit、Permit2 的六种格式、Seaport 官方合约的挂单。签名机会用中文写明"授权给谁、多少额度、何时过期"，或者"你给出什么、收到什么、付给谁"。
   - 挂单里你什么也收不到，或者收到的全是无法核实价值的东西：标红警告。
   - 认不得的类型：写明"签名机看不懂"。
   - 不管认不认得，一律要勾选确认才签。确认要求写在 Rust 里，界面绕不过去。
4. **链要对**：表格里写的链和请求里的链不一致，拒签。表格里没写链，提醒"这份签名在任何链上都能用"。

**passphrase 模式**：passphrase 相当于第 25 个单词。它最大的坑是：输错不会报错，而是悄悄进入另一个空钱包，你可能就往那个钱包收款了。现在的做法：
- 解锁时明确选"passphrase 钱包"，必须输两次且一致。
- 可以填上次记下的 8 位"指纹"。签名机核对算出的钱包指纹，不一致就不让进；助记词保留，只需重输 passphrase。
- 解锁后每页顶部都显示"passphrase 钱包 · 指纹 xxxxxxxx"，随时知道自己在哪个钱包里。

**区块浏览器网址**：签名机地址下方显示 mempool.space、Etherscan 等网站的网址。它只是文字，点不了，签名机里也没有任何能打开网址的代码。你可以在另一台联网设备的浏览器里照着输入。观察机本来就联网，所以那边给的是可以直接点的链接。

## 4. 怎么证明它是对的

### 4.1 EIP-712

| 证据 | 结果 |
|---|---|
| 规范示例（Mail） | 类型哈希、域分隔符、消息哈希、最终摘要与 EIP-712 规范逐字节一致；用规范里的 "cow" 私钥签名，r / s / v 与规范一致 |
| 独立 Python 实现 | 6 组（含 MetaMask v4 数组示例、全部基本类型、Permit、Permit2、递归类型 + salt）摘要逐字节一致 |
| 审查员的边界测试 | 整数边界（int256 / uint256 等 ±1 共 20 个点）、类型名排序、互相递归、空结构等 11 个边缘用例，与参考实现全部一致 |
| 端到端 | Permit 经动画二维码（每 3 帧丢 1 帧）→ 签名机审查签名 → 观察机核对；同一签名冒充另一份数据被识破 |
| 签名机 C 接口 | 结构化签名不勾选确认 → 拒签；勾选后签名，观察机核对通过；链 ID 不符 → 拒签 |
| 拒签 | 重复键、多余字段、数值越界、非 UTF-8、校验和错误的地址、`uint+8` 等不规范类型、超长字段、65 个类型（立即返回，审查中构造的同类数据原本要算 20 多秒） |
| 识别 | Permit2 批量与 witness、未知结构的 Permit2、假 Seaport 合约、收款为 0 的挂单、只收到 NFT 的挂单、DAI 撤销授权：全部按预期显示与警告；每个被签名的字段都有对应的显示行，且都是高风险 |
| 模拟器 | 观察机粘贴 Permit JSON：显示"代币 Permit 授权"、无限额、被授权方、2030-01-01 到期、全部字段与警告，动画二维码 8 段，从截图解码出的帧序号递增；被输入法改乱的 JSON 当场被拒（截图在 `build/screens/p2a2-*.png`） |

### 4.2 passphrase 与浏览器网址

| 证据 | 结果 |
|---|---|
| 指纹核对 | 预期指纹不符 → 拒绝解锁，passphrase 清除、助记词保留，之前解锁的账户全部丢弃；重输正确的 passphrase 后解锁成功；连续三次输错、不重设直接解锁也都被拒 |
| 链接探针（C 语言调用真实静态库） | 接口版本 4、指纹不符被拒、助记词保留：28 项全部通过 |
| 模拟器 | 两次不一致与太短时提示；错误的预期指纹被拒；解锁后每页顶部显示"passphrase 钱包 · 指纹"；地址页显示各链浏览器网址文字 |
| 网址不能被篡改 | 地址含字母数字以外的字符（`/`、`@`、`?`、`#`、全角字符等）就不生成网址；签名机界面只用不解析链接的纯文字控件 |
