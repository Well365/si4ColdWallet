# P1 费曼汇报（下半程）：比特币测试网的"观察机 ↔ 签名机"闭环

日期：2026-10-10 · 状态：P1 下半程完成；真机、第二台电脑、测试网实际广播三项需要你的配合（见第 7 节）

> 费曼法：如果不能用大白话讲给外行听懂，就说明自己还没真正弄懂。讲不清的地方，就是要补的缺口。

## 1. 一句话

两台手机之间只靠扫二维码，就能完成一笔比特币测试网转账：观察机起草，签名机逐项核对后签字，观察机再核对签字、拼成可广播的交易。这条路在自动化测试里已经端到端跑通，在模拟器里跑通了"签名机导出账户 → 观察机导入"这一段。

## 2. 讲给外行听

**两台手机的分工**：签名机像锁在保险柜里的公证员，永远不联网，只认二维码；观察机像跑腿的秘书，能上网查余额、起草付款单，但手里没有印章（私钥）。

**动画二维码（UR 喷泉码）**：一笔交易可能有几千字节，一张二维码装不下。我们把它拆成很多张"明信片"轮流播放。每张明信片上是几页内容"混在一起"的结果（异或）。接收方不用按顺序收、也不怕漏几张，只要收够数量，就能像解方程一样还原全文。这套规则是 Blockchain Commons 公开的标准，我们自己照着标准写，用它官方的测试数据逐字节核对。

**公证员不轻信**：秘书送来的付款单，公证员要自己重算每一个数，有一处对不上就拒签：

- 没附上"钱从哪来"的完整前序交易 → 拒签（防止谎报金额骗走手续费）
- 声称"找零回到你自己的地址"，但算出来地址不是你的 → 拒签（防止找零被换成攻击者地址）
- 要求一种"只签一部分"的特殊签名方式 → 拒签
- 混进了不属于本钱包的输入 → 拒签

**秘书也不轻信公证员**：签字回来后，观察机检查交易内容是否和自己起草的一模一样，每个签名都用自己算的数据验一遍，才拼成最终交易。

**这次的意外发现——"一锅炒出了串味"**：签名机和观察机的程序共用一部分代码。把两者放进同一次编译时，编译器会把两边要的"配料"（功能开关）合在一起，结果观察机的程序里混进了签名用的代码。现在改成两口锅分开炒，并加了一道检查：观察机的配料表里出现签名相关的东西就报警。

**第三轮安全审查——"厨房里的人能摸到主人的键盘"**：编译时会运行第三方的构建脚本。我们早已把它关进沙箱（不能联网、不能乱写文件），但审查人发现：沙箱里的程序可以往主人的终端里"塞按键"，等主人的终端读到，就以主人身份执行了任意命令。现在编译在一个没有终端的新会话里进行，沙箱也禁止了塞按键、启动其他程序、调用系统服务。
