# P2a 费曼汇报：以太坊 / BNB Smart Chain（EVM 链）

日期：2026-10-10 · 状态：P2a 第一部分完成（转账、代币、授权识别、消息签名）；EIP-712 结构化数据签名留到第二部分，目前一律拒签

> 费曼法：如果不能用大白话讲给外行听懂，就说明自己还没真正弄懂。讲不清的地方，就是要补的缺口。

## 1. 一句话

签名机现在也能看懂并签署以太坊、BNB Smart Chain 等 EVM 链的转账、代币转账与授权、消息签名。看不懂或高风险的内容，要么直接拒签，要么必须由用户逐条确认后才签。

## 2. 讲给外行听

**同一把钥匙，很多把锁**：以太坊、BNB Smart Chain、Polygon 等 EVM 链用的是同一套"地址规则"，所以一个账户在这些链上地址相同。区分它们靠"链 ID"：每笔交易都写明自己属于哪条链（EIP-155），在别的链上无效。签名机每次都把链名和链 ID 摆在第一行。

**"看到的就是签的"**：以太坊的签名对象是一串字节的 Keccak 哈希。签名机把这串字节**严格**拆开（RLP 编码只接受唯一的标准写法），逐项显示，再对**同一串字节**算哈希签名。只要拆解是严格的，"显示的内容"和"签名的内容"就不可能对不上。

**最常见的骗局是"授权"而不是"转账"**：
- `approve` 授权：签了以后，对方可以随时转走你的代币，不需要你再签字。"无限额授权"更危险。
- 还有一个坑是本阶段审查中发现的：ERC-20 代币和 ERC-721 NFT 的 `approve` 用的是**同一个函数编号**。同样一行数据，对代币来说"0"表示"撤销授权"，对 NFT 来说却是"授权 0 号 NFT"。签名机离线时分不清对方合约是哪一种，所以对不认识的合约，一律按高风险显示，也不再写"撤销"字样。
- 其他授权写法也一并识别：`increaseAllowance`、Permit2、DAI 式 permit。
- Safe 多签的 `approveHash` 等于"预先批准一笔看不到内容的交易"，直接拒签。

**消息签名也能骗人**：网页让你"签一条登录消息"。有些字符肉眼看不见，或者和英文字母长得一模一样（比如西里尔字母"а"），屏幕上显示"example.org"，签的却是别的域名。现在只有白名单里的字符（英文、数字、常用标点、中文）才按文字显示，其他一律显示成十六进制。另外，恰好 32 字节的"消息"很可能是一笔交易的哈希，签它等于盲签，现在直接拒签（见 D33）。

**两台手机显示一样的内容**：观察机构造交易后，调用的是与签名机**同一份**审查代码，生成的显示内容也一样。用户可以把两台手机逐行对照。如果观察机被篡改而签名机没有，两边就会对不上。

### 4.2 拒签与警告（都有测试）

| 场景 | 结果 |
|---|---|
| 请求声明的链 ID 与交易不符 / 地址不符 / 别的钱包的路径 / 非地址路径 | 拒签 |
| EIP-7702（类型 4）、blob（类型 3）、无链 ID 的旧式交易 | 拒签 |
| Safe DELEGATECALL、Safe `approveHash` | 拒签 |
| 数据类型与内容不符（类型化交易冒充旧式交易） | 拒签 |
| 链 ID 大到 EIP-155 的 v 放不下 | 审查阶段拒签 |
| 无限额 / 接近无限额授权、未知合约的授权（可能是 NFT）、Permit2、DAI permit、setApprovalForAll、未知合约调用、部署合约 | 高风险：界面要求勾选确认，Rust 也会再次检查（恰好 32 字节的消息已改为直接拒签，见 D33） |
| 观察机：请求号不符、签名被篡改、别的地址的签名、高 s 值、拼装结果与待签内容不一致、节点返回的哈希与交易不符 | 全部拒绝或报错 |

### 4.3 独立审查

| 审查 | 发现 | 处理 |
|---|---|---|
| EVM 安全审查（代码阅读 + 运行测试） | **无 CRITICAL**。核心性质"签名哈希 = 被解析显示的那串字节的哈希"成立。1 个有条件的 HIGH：ERC-721 的 `approve` 被当成 ERC-20 显示，"授权 0 号 NFT"会显示成"撤销授权"。3 个 MEDIUM：接近无限额的授权只给普通提示；消息文字过滤漏了不可见字符与同形字；`increaseAllowance`、Permit2、Safe `approveHash` 等未识别。6 个 LOW | 全部修复，并为每一项加了回归测试（`review_findings_regressions`）：未知合约的授权一律高风险且不写"撤销"；"极大额度"阈值；消息改为字符白名单；新增 4 种调用识别，`approveHash` 拒签；高风险确认改在 Rust 中强制；超大链 ID 在审查时拒绝；优先费异常警告；消息不再以未验证的链 ID 作标题；观察机拼装后逐字段复核、广播后核对交易哈希 |
| 安全审查五（P1 的复核，只读） | 无 CRITICAL / HIGH；4 个 MEDIUM 已修复 | 见 P1b 第 8 节 |

## 5. 我讲不清 / 没把握的地方（知识缺口）

| 缺口 | 为什么讲不清 | 怎么补 | 何时补 |
|---|---|---|---|
| EIP-712 结构化数据 | 还没实现；许多 DApp 的登录、挂单、Permit 签名都用它 | P2a 第二部分：自写严格 JSON 解析、按规范计算 hashStruct、Permit/Permit2/Seaport 等识别与高风险警告 | 下一步 |
| 未知合约调用仍可签（勾选确认后） | 威胁模型 T5 写"解析不完整就拒签"，EVM 表格又允许"未知合约调用强警告"，两处有张力 | 请你决定：是否改为"未知合约调用一律拒签"（更安全，但很多 DeFi 操作将无法使用） | 需要你的决定 |
| 真机扫码、真实广播 | 没有设备；模拟器里中文输入法会干扰自动输入，转账界面只验证到"导入账户、查余额" | 真机实测；领取 Sepolia / BSC 测试币后走一笔真实转账 | 需要你配合 |
| 代币表很小 | 只收录了以太坊与 BSC 上的 USDT、USDC、DAI；其他代币按"未知合约"显示原始数值 | 评估是否加入更多代币（每加一个都要核对合约地址） | P2 期间 |
| 手续费是否合理 | 签名机离线，无法知道当前链上费用水平；只能做绝对阈值检查（Gas 单价 > 1000 gwei、优先费 > 100 gwei） | 观察机可以在界面上对比多个节点的建议值 | P2 期间 |
| 人工审查 | `third_party/keccak`（约 500 行）待两名审查人确认 | 与其他第三方条目一起审查 | 需要审查人 |
| 苹果 nm 读不出 Rust 工具链的部分目标文件 | 静态库里 Rust 自带的 `compiler_builtins` 成员是新版 LLVM 位码，Xcode 自带的 nm（较旧的 LLVM）认不出。观察机构建脚本里原来的写法把这个错误静默吞掉了（本阶段发现并改为精确放行）；C4 检查的是链接后的可执行文件，不受影响 | 评估引入与 Rust 同版本的 llvm-tools（需按 R1/R4 核验），或改用自写的 Mach-O / ar 解析 | P2 期间 |

## 6. 和计划相比

- 按 `docs/06` 计划完成了 P2a 的大部分内容；EIP-712 拆到第二部分（在此之前一律拒签，不影响安全）。
- 计划外但必须做的：根据第四、五轮供应链审查继续加固构建流程（后台进程清理、产物拷出沙箱再链接、彻底去掉 `dlsym`）；根据 EVM 审查修复 1 个 HIGH、3 个 MEDIUM。
- 新增决策 D21（Keccak 来源）、D22（通用显示模型与签名机接口 v3）、D23（EVM 请求格式与签名约定）、D24（观察机显示与签名机相同的内容）。
