# P2c 费曼汇报：Solana 也能离线签名了

日期：2026-10-11 · 状态：代码完成、全部测试通过、两台设备的 App 都能编译；真机上实际发一笔需要 devnet 测试币（见第 7 节）

> 费曼法：如果不能用大白话讲给外行听懂，就说明自己还没真正弄懂。讲不清的地方，就是要补的缺口。

## 1. 一句话

离线的签名机现在能看懂一笔 Solana 交易、逐项讲给你听，然后签字；联网的观察机负责拼交易、查手续费、广播。

## 2. 讲给外行听

一笔 Solana 交易像一张"操作清单"：先列出用到的所有账户，再列出一条条指令（"从 A 转 1 SOL 给 B""创建代币账户""转 5 USDC"）。签名就是在整张清单上按手印。

最危险的不是"转账"，而是清单里夹带了别的东西：
- **改账户归属**（System Assign）：等于把你的账户交给别人的程序处置——签名机直接拒签；
- **交出代币控制权**（SetAuthority）——直接拒签；
- **地址查找表**：清单里只写"第 N 号地址"，真正的地址在链上，离线没法核实——直接拒签；
- **授权、关闭代币账户、不认识的程序**——红色警告，必须勾选确认。

还有一个容易被忽视的问题：代币不是直接转进"钱包地址"，而是转进对方的"代币账户"。签名机怎么知道这个代币账户真的属于你要付的人？办法是：观察机在清单里附上一条"如果对方还没有代币账户就创建一个"，里面写着钱包和代币；签名机自己按公开算法推导一遍，推导结果对得上，才显示"收款人（已核对归属）"。

## 3. 具体做了什么

| 产出物 | 位置 | 说明 |
|---|---|---|
| 消息解析 | `core/crates/aw-chain-sol/src/message.rs` | legacy 与 v0，严格检查 |
| 程序与 ATA 推导 | `programs.rs` | 已知程序、USDC / USDT、PDA |
| 审查 | `review.rs` | 拒签与告警规则、手续费、收款人核对 |
| 签名请求与签名 | `request.rs`、`sign.rs`、`watch.rs` | `sol-sign-request` / `sol-signature`，三种路径方案 |
| C 接口 | `aw-ffi-signer`、`aw-ffi-watch/src/sol.rs` | 错误码段 -400 |
| 观察机界面 | `ios/Watcher/Watcher/Sol*.swift` | 导入、余额、节点、优先费档位、发送、广播 |
| 独立实现 | `tools/testvectors/sol_message.py`、`sol_ata.py` | 只用 Python 标准库 |
| 决策 | `docs/05-decisions.md` D37 | 规则与边界 |

## 4. 怎么证明它是对的

- 全部 Rust 测试通过（本机实测）；其中 Solana 相关：解析器与独立 Python 实现 600 条一致，ATA 推导 60 组一致，签名与 RFC 8032 官方向量一致，三种路径方案的端到端（观察机 → 二维码 → 签名机 → 二维码 → 观察机）全部通过，任意截断 / 改字节不崩溃。
- C 接口测试：签名机侧审查、签名、高风险未确认拒绝、选错账户类型拒签；观察机侧构造、核对、交易号。
- 模拟器：观察机 Solana 页能导入地址、通过创世区块核对 devnet 节点、取到优先费三档、余额不足时给出正确提示。
- 独立复审：见第 5 节。
- **未验证**：真机之间的实际收发与广播。
