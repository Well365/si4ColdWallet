# D39 Feynman report: the Signer remembers the wallet and opens with a 6-digit PIN

Date: 2026-10-11 · Status: code complete, Simulator screen flow verified; the security review and the real-device test are not done (see the handoff `docs/handoff/2026-10-11-d39-pin-vault-handoff.md`)

## 1. In one sentence

The Signer can now keep the wallet encrypted on the phone, so opening it takes only a 6-digit PIN; one wrong PIN wipes the stored wallet.

## 2. Explained to a layperson

Before, the Signer was a safe that made you recite the whole combination every time: all 12 or 24 words, typed one by one. Very safe, but tiring.

Now the safe has a one-strike lock:
- the wallet sits in a box that opens only with this phone's own chip (the Secure Enclave) plus the 6-digit PIN;
- opening the app, or coming back from the background, asks for the PIN;
- one wrong PIN destroys the box, and the wallet must be restored from the words on paper, so the paper backup must be right;
- you can also choose "don't save" and keep the old way of working.

## 4. How we know it works

- `tools/ios/build-signer.sh sim` and `device` both end with all checks passing, artifacts included.
- Simulator: the set-PIN page, double entry, the save-failure message, "don't save" into the wallet, and the session being dropped after a trip to the background were all observed.
- **Not verified**: saving, unlocking and wipe-on-wrong-PIN on a real device (the Simulator has no Secure Enclave). **Not done**: the independent security review.
