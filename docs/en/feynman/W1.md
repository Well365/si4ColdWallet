# W1 Feynman report: the Watcher's "sending system" — choose the node, choose the gas, check the balance first

Date: 2026-10-11 · Status: code done and compiled for the simulator, installed on both phones; actually sending a testnet transaction needs your test coins (see Section 7)

## 1. In one sentence

The online phone (the Watcher) can now choose which node to send through and how much fee to pay, and it checks that the balance is enough before asking the Signer to sign.

## 2. Explained to a layperson

Sending a parcel raises three questions: which courier office, standard or express, and whether you can afford goods plus postage.
- **Node = courier office.** Each chain used to know a single office; if it closed, you could not send. Now each chain has several built in, each can be "health-checked" (right chain? which block? how fast?), you can add your own, and a signed transaction can be handed to a different office.
- **Gas = postage tier.** The price used to be chosen for you. Now "slow / standard / fast" are listed, each with its unit price and "maximum you could pay", and you can enter your own. The tiers come from what others actually paid in the last 10 blocks (10th, 50th, 90th percentiles), not a guess.
- **Balance first.** A QR code used to be generated even when funds were short, failing only at broadcast. Now "amount + maximum fee" is computed before building; if short, you are told where.
- **Fee and amount never mix.** Both devices now show "maximum total deducted (amount + max fee)", or "maximum deducted (fee only)" for token transfers — amount, fee and total each on its own row.

## 4. How we prove it is correct

- All Rust tests: `cargo test --workspace --locked --offline` → 179 passed, 0 failed (measured locally). New: tier rules (known inputs → known outputs, even-count median, zero base fee on BNB Chain, all-zero error, overflow, too much history), balance check (exactly enough / 1 wei short / token short / overflow), C-interface round trip, "maximum total deducted = 0.050063 BNB".
- clippy: 0 warnings in our code; rustfmt clean.
- Built-in nodes: each checked on 2026-10-11 with `eth_chainId`, `eth_feeHistory` and `eth_maxPriorityFeePerGas`; only working ones kept (LlamaRPC, 1RPC and rpc.sepolia.org were down; Cloudflare lacks `eth_feeHistory`). Esplora servers were checked for genesis block, tip height and both fee endpoints.
- Builds: C6 two-path reproduction matches; the Watcher simulator build compiles with no new warnings; the Signer compiles (artifact checks C4/C5 still fail on the known Xcode 27 issue).
- **Not verified**: actual sending and broadcasting on a real device (needs test coins).

## 5. Knowledge gaps

| Gap | Why unclear | How to close | When |
|---|---|---|---|
| Are the tiers enough under congestion? | Only 10 blocks of history; in a spike even "fast" may fall short | send several testnet transactions on device and watch confirmation times; tune multipliers | once test coins are available |
| Long-term availability of public nodes | working today ≠ working tomorrow | health checks on the node page + your own nodes | ongoing |
| Effect of a lying node | a node can report fake balances or fees | the Signer independently shows "maximum total deducted" and warns on abnormal fees; multi-node cross-checks later | later |
